# 数据划分与统计范围修订记录

## 最终报告的样本范围

报告的数据分布按最终保留的 Java 文件集合统计：984 条训练记录与 220 条共享功能评估样本，合计 1,204 条。企业信息化为 336/76，智慧物流为 408/102，智慧城市为 240/42（训练/评估）。领域柱状图、来源组成图、长度分布及其汇总 CSV 均按这些真实标识重新筛选计算，不将历史候选数量直接替换为 220。

220 个评估文件来自 `materials/data_construction/analysis/current_task3_source_index.csv`，训练记录来自归档 V4 索引的 Java train 部分。图表输入保存在 `materials/data_construction/analysis/data_complexity_records.csv`；原始来源索引与原始结果不改写。训练与最终评估的标识及完整源码无交叉重复，但共享来源仓库。报告不声称存在独立于验证用途的最终测试集。

## 历史运行与候选记录

原始 Java 来源索引有 1,226 条，其中 train 为 984 条、外部 eval 候选为 242 条；最终功能评估保留 220 条。正文仅报告最终分析范围，原始索引保持历史值。V4 启动入口明确传入外部 eval 文件，不触发入口中的 `test_size=0.05` 回退分支；因此不能根据该默认值推定这次运行又进行了内部切分，也没有发现 1:4 划分的有效依据。

历史 V4 入口实际载入的完整训练与验证记录包含其他语言，完整原始数量保存在训练材料中。本次正文围绕 Java 任务展开；984 是归档 Java 训练记录数量，不是对完整 V4 运行总样本数的重新定义。用户删除的其他语言训练描述不恢复。

## 训练曲线

训练与验证损失仍使用历史日志中的原始数值，保留 2,280 个训练步和 10 次逐轮验证记录。最终 220 个文件的功能比较与历史运行的词元交叉熵采用不同统计单位。报告省略无法确认的内部划分比例、监控集合与最终文件集合的精确对应及预测模型的具体训练轮次，不将原始损失重算或改称在 220 个文件上重新测得。

功能预测的历史服务标识为 `aixcoder-7b-v2-sft-0826`，现有记录仍不能映射到 V4 的特定权重或轮次。报告不将图中训练末轮或最低验证损失轮次指定为功能评估模型的来源。

## 校验

`analysis/verify_report.py` 同时校验原始索引的历史数量与最终分析集合的 984/220 数量，逐组复算分布中位数，并核对所有功能比较仍使用相同的 220 个目标文件。服务器保持只读，未重训、生成新预测或重跑工程测试。
